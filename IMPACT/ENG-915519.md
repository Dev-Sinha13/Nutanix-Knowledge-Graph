# ENG-915519 — Global IAM `authoringScope`

**Company impact:** Nutanix Central can tell *which product cluster authored* a global Role or Access Control Policy, and that origin cannot be rewritten later. This is the provenance primitive for Kronos. Every later ownership rule (ENG-949861) keys off this field.

Back: [IMPACT index](README.md) · Source: [inbox index](../inbox/ENG-915519%20-%20Global%20IAM%20authoringScope/00%20-%20Index.md)

---

## The customer / product problem

In a federated deployment, the same Role or ACP is visible on NC and on every joined PC because Lattice replicates **global** entities. Without a stored origin:

- The NC UI cannot label “authored on Nutanix Central” vs “authored on this Prism Central.”
- Downstream edit-gating has nothing durable to key on (a boolean `isGlobal` is not origin).
- Future federation patterns have no column to filter (`authoring_scope = 'NC'`).

A **non-global** (tenant-local) entity does not need this field. Only lattice-replicated globals do.

This is **not** the `products` field (ENG-932537). `authoringScope` = *who authored*. `products` = *what it applies to*. Independent columns, independent mutability.

---

## What shipped (the contract)

Design **locked 2026-06-01** after reviewer pushback (Aditya on ntnx-api-iam #910, Praveen on iam-themis #1601):

| Property | Locked value |
| --- | --- |
| Shape | **Scalar enum** `{NC, PC}` — not an array |
| Who writes it | Server only, at create |
| Who reads it | Clients (read-only on the OpenAPI model) |
| Empty | Omitted on the wire (`omitempty` / empty string) |
| Updates | SQL UPDATE **skips** this column (immutable) |
| Filter | Equality on a `text` column + b-tree (simpler than GIN array containment) |

Server stamp (`ComputeAuthoringScope`):

| Condition | Value |
| --- | --- |
| `isGlobal` + cluster is PC | `"PC"` |
| `isGlobal` + cluster is NC | `"NC"` |
| `isGlobal` + other product (e.g. Xi) | `""` (omitted) |
| not global | `""` (omitted) |

**Why scalar, not array.** An entity is authored on exactly one product. Multi-authorship is not in the Kronos design. Equality filters and a cheaper index beat `text[]` containment. If multi-origin ever appears, it should be a **new** field (e.g. `replicatedFrom`), not an overloaded `authoringScope`.

The earlier “array for forward-extensibility” framing was reversed in one coordinated push across all three PRs on 2026-06-01.

## Why this is company-visible

1. **NC console / IAM UX** can display origin without guessing from `isGlobal`.
2. **ENG-949861** can emit a 403 “managed by Nutanix Central” on PC because stored `authoringScope == "NC"` is a fact, not an inference.
3. **Lattice forward-compat:** `omitempty` means older peers ignore the field; new peers preserve it. Federation does not require a flag day on every cluster.
4. **Review quality:** 22 review comments were rolled up and classified (mechanical vs design vs bot). The array→scalar conversion is the design-lead-level outcome, not a drive-by.

## Engineering depth that protected the product

- **Five omitted SELECT lists** after migration/INSERT looked “done” but reads returned empty. Classic “column exists in DB, API returns blank.” Fixed by auditing every query constant.
- **Decision log kept split from open questions** so later sessions did not re-litigate scalar vs array.
- **Lattice:** only globals; skip column on UPDATE so replication cannot “re-author.”
- **Xi** is not a stamp value — empty, omitted. Avoids pretending Xi is an authoring product.
