# ENG-910347 — Resolver RPCs for shard read/write (ACP)

**Company impact:** When a Prism Central **first joins** the lattice consensus group, bulk **shard copy** (`FetchShardData` / `WriteShardData`) now carries the same identity rewrite as incremental ApplyChange. A brand-new PC does not persist **unresolved source-cluster UUIDs** until some later change happens to fix them.

## The customer / product problem

#1535 fixed create/update and ApplyChange. **Shard copy is how a newly joined PC gets the existing global ACP set in bulk.** Grep on `origin/master` showed **zero** enrich/resolve in `shard_data.go`. So:

- Incremental updates after join: correct UUIDs.
- Day-0 bootstrap: **wrong UUIDs stored**.
- Authorize on the learner against shard-copied ACPs: wrong principals until a later ApplyChange.

That is a **join-day** product bug, not a nice-to-have.

Themis-only. No public schema change (internal lattice RPC). identityresolver already vendored by #1535.

## What shipped (implemented + unit-tested; not committed in notes)

Faithful extension, no forked logic:

1. Transit-only `APEnrichedIdentities` map on `shardDataBatch` (`omitempty` for old/new peers). Per-AP because a batch holds many APs (unlike single-AP ApplyChange).
2. **Leader** `fetchAccessPoliciesBatch` — enrich where source UUIDs mean something.
3. **Follower** `WriteShardData` — resolve **before** tenant adaptation + persist, so raw cross-cluster UUIDs are never stored.
4. Reuse `#1535` helpers; export `EnrichAPIdentities` wrapper rather than renaming ~26 call sites.

**Degrade:** enrich/resolve failure is **hard-fail / retryable**, not “copy verbatim.” Verbatim fallback would silently persist stale UUIDs — the worst production failure mode.

Collision: OPEN [PR #1607](https://github.com/nutanix-core/iam-themis/pull/1607) (ENG-811163 selective ACP persistence) edits the same `WriteShardData` block. Correct order: **filter → resolve survivors → adapt → persist**. Semantics compose; text conflicts. Delivery sequencing left open (D7).

## Why this is company-visible

1. **Correct IAM on cluster join**, not only on later edits.
2. **No silent wrong-UUID store** (hard-fail vs fallback).
3. **Group identities** on shard copy, not only users.
4. Worktree discipline (`iam-themis-shard-acp`) because parallel agents were switching the shared checkout (same class of bug as 915519/932537).
