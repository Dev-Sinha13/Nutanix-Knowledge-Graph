# ENG-953364 — Run-once completion contract (role `products` brownfield migration)

**Company impact:** Existing clusters that already have Roles must get `products` computed **once, for every tenant**, and only then may Bootstrap mark the migration **complete**. An empty tenant list is **not** success. Without this contract, NC could believe “products migration done” while brownfield roles still have empty `product_list` — federated filtering would be silently wrong.

## The customer / product problem

ENG-932537 added the field and seed paths for **new** objects. Brownfield Roles already exist. A one-shot migration must:

- Fan out per tenant.
- Recompute role `products` from accessible entities.
- Record **global completion** only after **every** tenant succeeds.

IAM Bootstrap is the global coordinator; Themis workers are tenant-scoped.

---

## The failure mode this ticket kills

**Empty successful tenant enumeration ≠ complete.**

If AuthN/tenant list returns zero tenants (wrong endpoint, wrong cluster, pagination assumption, or “not ready yet”), a naive coordinator would set the completion flag. Then:

- No worker ever runs.
- Completion stays set forever.
- NC filters on `products` as if the world were migrated.
- Operators see empty or default products on real roles.

ENG-953364 treats an empty tenant list as **retryable** and **leaves completion unset**. Other APIs may legitimately return zero objects; **this migration must fan out**, so the empty-list rule is **feature-specific**, not universal.

Also recorded: AuthN’s current v1 tenant list is **unpaginated** — that is an implementation fact, not a permanent API assumption. Verify pagination from the live endpoint.

---

## Architecture rules this encoded

- Global coordinators own fan-out and the **final** completion decision.
- Tenant-scoped workers process **exactly one** tenant and report success/failure.
- Global completion flag is written **only after every tenant succeeds**.
- Do not copy Lattice `WalTenantID` tablet-copy assumptions onto arbitrary bootstrap batches.

---

## Why this is company-visible

1. **Upgrade safety** for Global IAM / NC filtering on already-deployed fleets.
2. **No false “green” migration** that support cannot diagnose (flag says done, data says empty).
3. Prevents a class of bugs where “success on zero work” looks like a passed pipeline.
