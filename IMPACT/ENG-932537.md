# ENG-932537 — IAM `products` field

Back: [IMPACT index](README.md) · Engineering notes: [inbox index](../inbox/ENG-932537%20-%20IAM%20products%20field/00%20-%20Index.md)

---

## 1. The problem

Nutanix Central sits above **multiple products and clusters**. IAM Entities are seeded per cluster from `objects.json`. Roles grant operations on those entities. A federated IAM view that cannot answer **“is this a PC object or an NC/NCM object?”** is not a global console — it is a dump.

There was no stable, API-visible **product membership** tag on Entities and Roles that:

- NC could `$filter` on
- survived lattice for **global roles**
- was seeded correctly at bootstrap (not only declared in JSON)

`authoringScope` (who authored) does not solve this. A role can apply to NC and PC products and still be locally editable if it is not global.

---

## 2. How it was solved

A **read-only multi-valued** field `products` (`[]string` / Postgres `text[]`, default `'{}'`):

- **Entities:** declared in `objects.json` as `productList`, seeded per cluster (Lattice does **not** copy entity products; each cluster seeds the same values).
- **Roles:** **server-derived** union of entity `product_list` across every entity the role’s operations act on; recomputed on **every create and update** (`ComputeAccessibleEntitiesList`). Client-supplied role products are overwritten.
- **Allow-map** (bootstrap config-load, not Themis runtime): PC → `["PC"]`; NC → `["NC","NCM"]`. Not `AHV`, `CALM`, `UNKNOWN`, `Xi`.
- **AccessPolicies: out of scope.** Q-L3 wired them, then **D24 reverted** them. APs are grants, not product membership.

Surfaces: entity v1 GET/LIST/filter + v4 GET/LIST/OData + v1 `/load-objects` and `/proxy` write; role v4 GET/LIST (derived). Role v1/proxy deferred.

---

## 3. Impact

- **NC UI** can filter federated IAM (`products/any(p: p eq 'NC')`).
- **Bootstrap hole closed:** both v1 `loadObjects` and v4 `SeedEntitiesV4` were **silently dropping** `ProductList`. Schema without seed is an empty column in production after upgrade.
- **Wrong product surface avoided:** shipping `products` on AccessPolicies would have invited NC to filter *grants* as if they were product membership. Rollback is the impact as much as the feature.
- **Unlocks brownfield work:** ENG-953364 / ENG-956163 exist because existing Roles must be backfilled **honestly**.

## 4. How it was done

Four-repo chain, top-down by schema, bottom-up by dependency:

```
ntnx-api-iam #914  (v4 Entity + Role schema; AP yaml removed)
    → iam-utils #358  (ConfigObject/Role types, ProductAllowedTypesMap)
        → iam-themis #1603  (storage, handlers, tavern)
iam-bootstrap #768  (seed v1 + v4; reads the same config types)
```

Process in Themis:

1. Additive migration `ADD COLUMN IF NOT EXISTS product_list text[] DEFAULT '{}'` on `object` and `role` only.
2. Column lists, scanners (`pq.Array`), OData: **EDM `IsFilterable` and Go allow-list** — seed JSON is not OData metadata.
3. Entity path: `FromLoadObjectRequest` / `FromV4EntityRequest` → storage → v1 and v4 response builders.
4. Role path: collation helper unions entity products on create **and** update.
5. **Turn-start audit before planning** (see difficulties): grep vendor models, converters, column lists, filter maps — *then* write the plan.
6. Where Themis needed unmerged upstream DTOs: **TEMP HACK vendor edit the same day as the canonical upstream PR**, then revendor after merge (`make revendor` = tidy + vendor + verify).
7. Tests: unit + tavern for entity v1/proxy and role v4 collation. ASCII-only YAML (Python 2.7 collector).
8. Logging discipline: `iam-themis/.notes/PRODUCTS_FIELD_CONTEXT.md` is part of the definition of done (decisions, files, gates, changelog). Cursor rule `.cursor/rules/iam-products-field.mdc` always-on for this initiative.

Manish’s parallel no-suffix `ENG-932537` branches were **not** reused.

## 6. Significant technical difficulties

**Planning a path that was already wired.** A 9-step plan to add `products` on the v1 load path (vendor models, handlers, filters) collapsed after two greps: `LoadObjectRequest.Products` existed, the converter already copied it, `ObjectSupportedFilterFields` already had `products`. Approach: **mandatory audit at turn start**; the plan must list what is already done. That is now a vault pattern (`audit-before-planning`).

**Silent seed drop.** `objects.json` had `productList`; runtime rows did not. Both bootstrap converters omitted the field. Approach: treat “JSON has it, DB doesn’t” as a **converter** bug, not a schema bug; fix v1 and v4 seed paths independently and test both.

**AccessPolicy products (D24).** Wired in Q-L3 then reverted (rebase dropped `a411a8943`; AP yaml removed from #914). Approach: keep reflog for forensics; do not leave a half-field on APs; document “Roles + Entities only” in the always-on Cursor rule so later sessions cannot re-add it casually.

**Vendor `gofmt -w` cascade (~30k-line diff for a 10-line add).** Mixed 2-space vs tabs in generated `authz_model.go`. Approach: restore vendor from HEAD, re-insert fields **byte-for-byte** in the file’s existing indent; never format whole generated files. Marker `TEMP HACK` comments also triggered “this isn’t generated” — switched to canonical-style vendor adds (D22).

**Python 2.7 Tavern + non-ASCII stage names.** Em-dashes in YAML `name:` fields → `UnicodeEncodeError` in the collector **before any test runs**. A first scrub missed a second document; those dashes sat on origin and were a **candidate cause of IAMv2 red**. Approach: ASCII-only as a precondition; `perl -CSD` scan **and** confirm the scan covered the whole file; scrub committed as its own tip (`7aa4c7c77`).

**Cross-repo IAMv2.** Themis-with-new-column vs trunk-bootstrap-without-seed (and the reverse) fails by construction until the merge train lands. Approach: do not “fix” feature code to satisfy a mixed-version rig; distinguish this from ASCII collector crashes; do not empty-commit to heal.
