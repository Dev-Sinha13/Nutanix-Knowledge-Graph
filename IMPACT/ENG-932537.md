# ENG-932537 — IAM `products` field

**Company impact:** Nutanix Central can **filter federated IAM Entities and Roles by product** (NC / PC / NCM). Without this field, NC can only list IAM objects globally — it cannot tell which underlying product an entity belongs to after federation.

Back: [IMPACT index](README.md) · Source: [inbox index](../inbox/ENG-932537%20-%20IAM%20products%20field/00%20-%20Index.md)

---

## The customer / product problem

NC sits above many clusters and products. IAM Entities are seeded per cluster from `objects.json`. Roles grant operations on those entities. A federated IAM view that cannot answer “is this a PC object or an NC/NCM object?” is not usable as a **global** console.

`products` is the stable tag that:

- Survives lattice replication for **global roles** (`omitempty` so older peers ignore unknown JSON).
- Is **seeded independently** on each cluster for **entities** (not copied by Lattice — same values because seed data is the same, not because of replication).

This is **not** `authoringScope`. A role with `products: ["NC","PC"]` can still be locally editable on PC if `isGlobal=false`. Edit permission is `isGlobal` + `authoringScope`, never `products`.

## What shipped (the contract)

| Item | Contract |
| --- | --- |
| Field | `products` (JSON), Go `ProductList []string`, Postgres `text[]` default `'{}'` |
| Entities | Declared in `objects.json` as `productList`; flows ConfigObject → load/seed → `storage.Object` |
| Roles | **Server-derived** union of entity `product_list` across every entity the role’s operations act on; recomputed on **every create and update** (`ComputeAccessibleEntitiesList`) |
| Allowed values | PC cluster: `["PC"]`. NC cluster: `["NC","NCM"]`. Via `configutil.ProductAllowedTypesMap` at **bootstrap config-load**, not runtime Themis validation |
| Not allowed | `AHV`, `CALM`, `UNKNOWN`, `Xi` (`Xi` exists as a runtime product constant but is not in the allow-map) |
| User writes | Rejected / ignored. Read-only API |
| AccessPolicies | **Out of scope.** Wired in Q-L3, **reverted 2026-05-29 (D24)** |

Surfaces (abbreviated — full matrix in inbox `07 - API Surface Matrix`):

- Entity: v1 GET/LIST + filter/select, v4 GET/LIST + OData, v1 `/load-objects` and `/proxy` write.
- Role: v4 GET/LIST + filter (derived). **v1/proxy roles deferred.**
- AccessPolicy: removed from all surfaces.

## Why this is company-visible

1. **NC topology-aware IAM UI** — filter `products/any(p: p eq 'NC')` on v4 LIST.
2. **Correct seed data at bootstrap** — both v1 `loadObjects` and v4 `SeedEntitiesV4` were **silently dropping** `ProductList`. NC would have shown empty products after upgrade even if schema existed. Fixed in iam-bootstrap [#768](https://github.com/nutanix-core/iam-bootstrap/pull/768).
3. **Scope discipline** — AccessPolicy products would have been the wrong product surface (APs are grants, not product membership). Rolling that back (D24) prevented shipping a field NC would misuse for filtering grants.
4. **Later migrations** — ENG-953364 / ENG-956163 exist because brownfield roles need a **run-once completion** and **ETag-safe** recompute. This ticket is the field; those tickets are “make existing clusters true.”

## Engineering depth that protected the product

- **Audit before planning.** A 9-step plan to add `products` on the v1 load path collapsed to **two greps**: vendor model, converter, and filter allow-list were already wired. Shipping the 9-step plan would have been churn and review noise.
- **TEMP HACK + upstream PR same day** so Themis could compile before utils merged — then cleanup by revendor.
- **Never `gofmt -w` vendor** — mixed-indent generated files cascade into unreviewable diffs.
- **ASCII-only Tavern** — a single em-dash in a stage name can fail the entire IAMv2 collector before any assertion runs.
- **Additive migration** `ADD COLUMN IF NOT EXISTS product_list text[] DEFAULT '{}'` — existing rows empty, not NULL; object + role tables only.
- **OData needs two edits:** EDM `IsFilterable` **and** Go allow-list. Seed JSON is not OData metadata.
