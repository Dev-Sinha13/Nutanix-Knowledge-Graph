# Repository Map

Three repos collaborate to deliver authoringScope. Each owns a different layer of the stack.

## ntnx-api-iam — public schema

- **What it owns:** The public v4 IAM API schema in IDL (YAML). Defines what external clients see.
- **Key files:**
  - `iam-api-external/iam-api-definitions/defs/.../authz/beta/models/access_policy.yaml` — ACP request/response shape
  - `iam-api-external/iam-api-definitions/defs/.../authz/beta/models/roles.yaml` — Role request/response shape
  - `iam-api-external/iam-api-definitions/defs/.../authz/beta/models/authoring_scope.yaml` — extracted enum model (new in 2026-05-28)
  - `iam-api-external/iam-api-definitions/defs/.../iamDefsDescriptions.yaml` — DocRef texts
- **Build:** Maven (`mvn install`). Validates schemas, runs schema-review-tool, generates Go stubs and Python SDK.
- **PR:** [[04 - PR Status|PR #910]] (branch `add-authoring-scope`)

## iam-utils — internal API + generated Go models

- **What it owns:** The internal Themis API in `themisutil/themis.yaml` (Swagger 2.0), plus the Go models that iam-themis consumes for service-to-service traffic.
- **Key files:**
  - `themisutil/themis.yaml` — internal API definition (Swagger 2.0)
  - `themisutil/generated/models/*.go` — generated by `go-swagger` (the version pin is one of the blockers; see [[09 - Open Questions & Blockers]])
- **Build:** `swagger generate model -f themisutil/themis.yaml -t themisutil/generated/`, then standard `go build` / `go test`.
- **PR:** [[04 - PR Status|PR #357]] (branch `ENG-915519-add-authoring-scope`)

## iam-themis — the service

- **What it owns:** The backend IAM service. Implements API handlers, the storage struct, SQL persistence, and the schema migration.
- **Key files:**
  - `services/server/storage/storage.go` — `storage.Role` and `storage.AccessPolicy` structs
  - `services/server/storage/util.go` — `ComputeAuthoringScope` helper, filter allow-lists
  - `services/server/storage/sql/role.go` and `access_policy.go` — INSERT / scan paths
  - `services/server/storage/sql/migrate.go` — the additive migration
  - `services/server/apihandler/v4_roles.go` and `v4_access_policy.go` — v4 converters
- **Build / test:** `go build` / `go test` with `-mod=vendor` for CI parity.
- **PR:** [[04 - PR Status|PR #1601]] (branch `ENG-915519-authoring-scope-handler`)

## Dependency direction

```
ntnx-api-iam (PR #910)  →  iam-utils (PR #357)  →  iam-themis (PR #1601)
   public schema             internal API model       handler + storage
```

The downstream repos vendor in the upstream ones, so **merge ordering is strict**:

1. PR #910 first (public schema)
2. PR #357 second (revendors / regenerates against new schema)
3. PR #1601 third (revendors both upstream repos)

See [[05 - Cross-Repo Flow]] for the data path at runtime.
